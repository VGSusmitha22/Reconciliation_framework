Key Flask wiring decisions

Flask is synchronous by default — to support streaming Claude responses and real-time recon progress, this stack uses Flask-SocketIO with the eventlet async worker, and Server-Sent Events (SSE) for one-way AI token streaming. Gunicorn must be run with the eventlet worker class (not the default sync worker) for SocketIO to function correctly in production. Pydantic is added manually for request validation — Flask does not include it natively.

02 — Blueprint Structure

Flask application factory pattern

All routes organised into Blueprints — registered on the app factory at startup

FACTORY

create_app() — Application factory

Initialises Flask extensions (db, migrate, jwt, socketio, limiter, cors) and registers all Blueprints. Config loaded from config.py using environment-based class inheritance — DevelopmentConfig, ProductionConfig. Celery instance created separately and shares the same config.

app/__init__.py
AUTH

Blueprint: /api/auth

Routes: POST /login · POST /refresh · POST /logout · GET /me. JWT managed by Flask-JWT-Extended with access token (15 min) and refresh token (7 days). Tokens set as httpOnly cookies. OAuth2 (Google, Microsoft Entra) handled via Authlib.

flask-jwt-extended
CONN

Blueprint: /api/connections

Routes: GET / · POST / · POST /{id}/test · DELETE /{id}. Connection strings encrypted with cryptography.fernet before storage in PostgreSQL. Decrypted only at query time inside the Celery worker — never returned in API responses.

Fernet encrypted
RECON

Blueprint: /api/runs

Routes: POST / · GET / · GET /{id} · GET /{id}/results. POST / enqueues a Celery task and returns run_id immediately. Results are paginated — large diffs returned in pages of 500 rows via query params. SocketIO emits progress events to the client room keyed on run_id.

Celery + SocketIO
AI

Blueprint: /api/runs/{id}/analyse

Routes: POST /analyse · GET /narrative · GET /narrative/stream. The /stream endpoint uses Flask's Response(stream_with_context(generate())) pattern with text/event-stream content type to push Claude tokens to the client as SSE. Final narrative persisted to PostgreSQL.

SSE streaming
CHAT

SocketIO namespace: /chat

Flask-SocketIO handles the RAG chatbot via a dedicated namespace. On message event, the server retrieves context from ChromaDB, runs Ollama inference, and emits token-by-token back to the client via emit('token', ...). Chat history stored in Redis per session ID with a configurable TTL.

Flask-SocketIO
EXPORT

Blueprint: /api/exports

Routes: POST /runs/{id}/export · GET /exports/{file_id}. Export generation (Excel, PDF, CSV) dispatched as a Celery task. Completed files written to S3 or local object store. A pre-signed download URL with 24-hour expiry is returned. Nightly Celery beat task cleans up expired exports.

S3 + signed URLs
ADMIN

Blueprint: /api/admin

Routes: GET /users · POST /users/invite · PATCH /users/{id}/role · GET /audit-log. Protected by an admin_required decorator that checks the role claim in the JWT. Audit log entries written by a SQLAlchemy event listener on every model write — no manual logging calls needed.

RBAC decorator

04 — Background Jobs

Celery task queue

Redis as broker and result backend · tasks are idempotent and retryable · Celery Beat for scheduled jobs

01

run_reconciliation

Pulls source and target data via SQLAlchemy, runs the DuckDB full-outer-join diff in a sandboxed worker process, categorises mismatches, writes results to PostgreSQL. Emits progress events to the Flask-SocketIO server via Redis pub/sub — the SocketIO server forwards them to the correct client room keyed on run_id.

Core job
02

generate_narrative

Serialises mismatch summary, sends to Claude API with a structured prompt. Streams tokens into Redis pub/sub — the SSE endpoint on the Flask server reads from this channel and pushes tokens to the waiting client response. Final narrative persisted to the run record in PostgreSQL.

AI job
03

embed_run

Chunks mismatch details, column mappings, and narrative. Embeds with nomic-embed-text via Ollama. Upserts into ChromaDB with run and org metadata. Checks the rag_index table first — skips embedding entirely if the run was already embedded with the same model version.

RAG prep
04

generate_export

Builds Excel (openpyxl), PDF (reportlab), or CSV from run results. Writes to S3-compatible object store via boto3. Records the file reference in PostgreSQL. Returns a pre-signed URL valid for 24 hours. A nightly Celery Beat task scans and purges expired export records and files.

Export job
05

cleanup_exports (scheduled)

Celery Beat cron task running nightly. Queries PostgreSQL for export records past their expiry, deletes the corresponding S3 objects, and removes the database records. Also purges expired Redis chat session keys and stale SocketIO rooms.

Celery Beat
05 — Multi-tenancy & Auth

Organisation-scoped data model

Every resource is scoped to an org_id — enforced at the SQLAlchemy model layer via a base query class

🔐

JWT Authentication

Managed by Flask-JWT-Extended. Short-lived access tokens (15 min) and rotating refresh tokens (7 days) set as httpOnly cookies. Token blocklist maintained in Redis for instant revocation across devices.

🏢

Organisation Isolation

A custom SQLAlchemy OrgScopedQuery base class automatically appends WHERE org_id = :current_org to every query. Cross-org access is structurally impossible — not just a policy check.

👥

Role-Based Access Control

Three roles: Admin, Analyst, Viewer. Enforced via custom Flask decorators (@admin_required, @analyst_required) applied directly to route functions — clear and explicit.

🔑

SSO / OAuth2

Google Workspace and Microsoft Entra ID via Authlib Flask integration. User auto-provisioned on first SSO login, mapped to org by email domain. Works alongside standard email/password auth.

📋

Audit Trail

A SQLAlchemy event.listen(after_flush) hook captures all write operations automatically. Writes to an immutable audit_log table with user ID, org ID, timestamp, IP address, and action metadata.

🗝️

API Key Access

Orgs can generate scoped API keys for programmatic access. Keys are bcrypt-hashed before storage and validated against a Flask before_request hook on API key-protected routes. Rate-limited per key via Flask-Limiter.

Flask-Migrate for schema versioning

All schema changes are captured as Alembic migration scripts via flask db migrate and applied with flask db upgrade. Every migration is reviewed before applying to production — no auto-apply in CI. Downgrades are tested for every migration to ensure rollback is always possible.

07 — Tradeoffs

Flask vs FastAPI — honest comparison

For this specific app, both can deliver the same features — the differences are in how much you wire manually

Flask — what you gain

Mature ecosystem — Flask-SQLAlchemy, Flask-Migrate, Flask-JWT-Extended, Flask-Limiter are battle-tested in production
Explicit and readable — every extension is registered visibly; nothing is hidden behind framework magic
Flask-SocketIO is the de facto standard for WebSocket in Python web apps
Easier to find Flask developers — larger talent pool, more Stack Overflow answers
Simpler mental model for teams unfamiliar with async Python

FastAPI — what you trade away

Native async — no eventlet patching required; true async I/O throughout with asyncio
Pydantic v2 built-in — request/response validation is automatic, not bolted on
Auto-generated OpenAPI docs at /docs — zero extra work
Dependency injection system — cleaner route guards and shared logic than decorators
Slightly higher throughput under concurrent load due to true async request handling
★

Recommendation

If your team already knows Flask well, go Flask — the ecosystem is mature enough to deliver every feature in this spec without compromise. If you're starting fresh with no strong preference, FastAPI has a slight edge for an AI-heavy app with streaming and real-time features, because async is native rather than patched in. Either is a legitimate production choice.

08 — Security

Production security checklist

Same security posture as the FastAPI version — Flask extensions cover every requirement

Credential Encryption

Database connection strings encrypted with Fernet (AES-128-CBC) via the cryptography package before storage. Encryption key loaded from environment only — never stored in the DB.

HTTPS Only

Nginx terminates TLS. HSTS enforced. Cookies are Secure + SameSite=Strict. Flask-Talisman sets security headers (CSP, X-Frame-Options, HSTS) automatically.

Rate Limiting

Flask-Limiter with Redis storage backend. Per-IP limits on auth endpoints (5 req/min). Per-org limits on AI endpoints to control Claude API spend. Custom error responses on limit hit.

Input Validation

Pydantic v2 added as a standalone dependency for request body validation. All database queries use SQLAlchemy parameterised statements — no raw string interpolation anywhere in the codebase.

CORS Policy

Flask-CORS configured with an explicit origins allowlist — only the known React frontend origin. No wildcard origins. Credentials allowed only for the whitelisted origin.

Secret Management

All secrets (DB URL, Claude API key, Fernet key, JWT secret key) loaded via environment variables or a secrets manager. python-dotenv for local dev — environment injection for production containers.
